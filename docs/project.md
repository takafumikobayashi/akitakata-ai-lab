# あきたかたAI Lab Webサイト — プロジェクト設計

最終更新: 2026-10-24

## 1. 活動の背景と約束

「あきたかたAI Lab」は、安芸高田でAIを「知る・触る・つくる」ことを地域の人たちと一緒に楽しむ、個人主催・非営利の地域コミュニティです。完成した講座やスクールではありません。小さく始め、参加者の「やってみたい」を聞きながら活動を育てます。

- **Mission:** AIを、地域の誰もが使える力にする。
- **Vision:** 安芸高田を、AIを「試す・作る・活かす」が日常にあるまちへ。
- **Values:** ①まず、触ってみる ②一緒に、作ってみる ③新しいものを、面白がる ④地域で、活かしてみる ⑤外へ、発信する
- **大切な明記:** 個人活動であり、安芸高田市の公式事業・イベントではありません。
- **問い:** 「あなたなら、AIで何をやってみたいですか？」

肩書を前面に出すのではなく、地域の人と一緒に試す姿勢を伝えます。主催者プロフィールには経験を簡潔に記載し、個人活動であることを近くに明記します。

## 3. 情報設計

初期MVPはホームの1ページで必要な情報に届く構成とします。ナビゲーションはページのアンカーに結び、活動量が増えた段階で独立ページへ切り出します。

| 領域      | MVPで見せる内容                   | 将来の拡張                             |
| --------- | --------------------------------- | -------------------------------------- |
| Home      | 活動の約束、次回イベント、参加CTA | 活動の新着や注目記事                   |
| About     | Labの目的、進め方、Values         | 活動の歩み、よくある質問               |
| Events    | 第1回の開催情報と申込リンク       | 開催予定・過去イベント一覧、各回の詳細 |
| Lab Log   | 記録をこれから蓄積することを案内  | 実験、成果、失敗、学びをMarkdownで掲載 |
| Knowledge | ナレッジの方針を案内              | AI活用ノウハウ、プロンプト、ツール紹介 |
| Join      | 既存Googleフォームへの参加導線    | 参加者の声を受け取る方法               |
| Profile   | 小林崇文の紹介と個人活動の明記    | 必要に応じてプロフィール詳細           |

MVPでは公開実績を捏造せず、開催前のLab LogとKnowledgeは「これから記録する」状態として表現します。アイデア例は、初回で全て実施する約束ではないことが伝わるようにします。

## 4. 技術設計

- **アプリ:** SvelteKit + TypeScript
- **スタイル:** Tailwind CSS v4。色、余白、タイポグラフィは専用トークンと少量のCSSで整える
- **Markdown:** MDsveXを導入済み。Lab Log / Knowledgeの記事をGitで管理できるようにする。MVPでは記事一覧・投稿機能を増やさない
- **ホスティング:** Cloudflare Workers with Assets + `@sveltejs/adapter-cloudflare` + Wrangler
- **データベース:** MVPでは使わない。開催情報など少量の構造化データはTypeScript、記事はMarkdownで管理する
- **連絡・申込:** 既存のGoogleフォームへリンク。APIキー、認証情報、個人情報を含む独自フォームは作らない

2026-10-24時点のCloudflare公式案内では、Workersを新規アプリの主軸として案内し、SvelteKit向けにWorkers Assetsと`adapter-cloudflare`を説明しています。したがって新規プロジェクトはPagesではなくWorkersを選択しました。

## 5. 画面の構成とデザイン

1. ヘッダー: ロゴ、ナビゲーション（1080px以下はメニューボタンで開閉）、参加CTA
2. ヒーロー: 大きなワードマーク「あきたかた AI Lab」、Mission、参加CTA、田園風景の水彩スケッチ（`hero-sketch-*.webp`）と「#01」バッジ
3. (01) Labについて: 「AIは、一部の詳しい人だけのものではありません。」、小さく始める活動、市の公式事業ではないこと
4. (02) 第1回のご案内（濃色セクション）: 大きな日付、内容、会場・住所・参加費・定員・対象・持ち物・締切、Googleフォーム
5. (03) やってみたいこと: 罫線で区切った6つのアイデア（神楽写真を含む）
6. (04) 大切にしたいこと: 5つのValuesを番号付きの行で表示
7. (05) 主催者: 顔写真（`organizer.webp`）、小林崇文の経験、主な活動、個人活動であること
8. (06) 資料: コンセプトスライド（企画案PDF全12枚のうち、運営者向けの相談内容だった10・11枚目を除く10枚）とチラシ（表・裏）を、タブで切り替えるスライドビューアー（`SlideViewer.svelte`）で表示。←→キー、スワイプ、クリック、サムネイル、全画面に対応。スライドの一覧と代替テキストは`src/lib/data/site.ts`の`decks`で管理
9. (07) 関連リンク: 主催者のサイトなどをOGP画像付きのカードで紹介。`src/lib/data/site.ts`の`relatedLinks`に追加し、OGP画像は`static/images/links/`にWebPで保存
10. Lab Log / Knowledge: 開催後に記録を始めることを1段で案内
11. 参加CTA: 「あなたなら、AIで何をやってみたいですか？」と、木造校舎の水彩スケッチ（`school-sketch-*.webp`）

チラシの青い「AI Lab」、黄色のマーカー、芽のロゴ、山並み、「#01」バッジを受け継ぎつつ、わずかに温かみのある白（#fafaf8）の背景・墨色の文字・細い罫線で、落ち着いた洗練されたトーンにまとめます。横幅は最大約1440pxまで広げ、色は青・黄・緑を差し色に限定します（Valuesの番号のみチラシの5色）。風景は撮影場所が特定されないよう実写ではなくイメージスケッチを使います。主催者の写真を含め、画像はWeb用に縮小し、位置情報などのメタデータを除いたWebPで`static/images/`に置いています（原本は`tmp/`に保管し、Gitの管理対象外）。見出しは Inter Tight（英数字）と Noto Sans JP（Google Fonts）で、本文は16px以上を基本とします。

スクロールに合わせて要素がフェードインする演出は、`data-reveal`属性と`src/lib/reveal.ts`（IntersectionObserver）で実装しています。`data-reveal="120"`のように値を入れるとミリ秒単位で遅らせられます。OSの「視差効果を減らす」設定が有効な場合は演出なしで表示し、JavaScriptが動かない場合も数秒後に全要素を表示します。

## 6. MVPロードマップ

### Phase 1 — 2026年11月8日まで

- 活動紹介と第1回イベントの情報をホームに掲載
- 申込フォームへ迷わず進めるCTA
- 主催者プロフィールと「市の公式事業ではない」説明を明記
- Lab Log / Knowledgeは後から記事を追加できる構成と案内を用意
- スマートフォン表示、キーボード操作、ビルド・lint・型チェックを確認

### Phase 2 — 初回開催後

- 実際に試したことをLab Logに記録
- AIの使い方や地域で見つけた知見をKnowledgeに掲載
- 記事が増えたら一覧・詳細ページを追加

Lab Logの基本フォーマット: **何を試したか / 使ったAIや道具 / どうなったか / 分かったこと / 次に試すこと**。

### Phase 3 — 参加者とのコミュニケーション

参加者のニーズが見えた段階で、アイデア投稿、テーマ投票、成果物共有を検討します。個人情報の扱い、公開範囲、運営負荷を決めてから必要なフォームやデータベースを選定します。最初から独自SNSや会員システムは作りません。

## 7. 公開前に運営者が確認する内容

- 研修室402の施設名・住所・入館案内
- 定員と申込受付状況、Googleフォームの公開状態
- 写真をWebに掲載する権利と、被写体の同意
- 主催者プロフィールの表記
- Cloudflare Worker名と公開設定。公開URLは `ailab.akitaka-note.jp`（`wrangler.jsonc` の `routes` に設定済み。`akitaka-note.jp` のDNSをCloudflareで管理していることが前提）

本作業ではCloudflareへログインせず、認証情報を作成・保存せず、本番デプロイを行いません。
